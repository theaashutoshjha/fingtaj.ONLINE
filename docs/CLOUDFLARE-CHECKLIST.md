# Cloudflare Crawler and AdSense Crawlability Verification Checklist

This checklist provides step-by-step instructions for confirming that Cloudflare security features, WAF rules, and managed bots settings do **not** inadvertently block Googlebot, Mediapartners-Google (the AdSense crawler), or AdsBot-Google from crawling **fingtaj.online**.

Google AdSense requires direct, unobstructed access to your web pages and `ads.txt` file. If Cloudflare challenges or blocks AdSense crawlers, your site will be rejected for "Site unreachable", "Low value content" (because crawlers cannot inspect the HTML), or "ads.txt not found".

---

## 1. Verify Cloudflare "Block AI Scrapers and Crawlers" Setting
1. Log in to the [Cloudflare Dashboard](https://dash.cloudflare.com/).
2. Select your domain (`fingtaj.online`) and navigate to **Security** → **Bots**.
3. Locate the toggle labelled **"Block AI scrapers and crawlers"** (or "AI Scrapers and Crawlers").
4. **Verification Step:**
   - While blocking untrusted scrapers is acceptable, Cloudflare's broad AI blocklist can occasionally include search or indexing bots if not configured carefully.
   - Ensure that Google search and indexing crawlers are explicitly exempted. In Cloudflare, **Googlebot** and **Mediapartners-Google** are classified under "Verified Bots".
   - Confirm that the Verified Bots setting is set to **Allow** or **Bypass**.

---

## 2. Verify Cloudflare Managed robots.txt Override
1. In Cloudflare Dashboard, go to **Rules** (or **Scrape Shield** / **Crawlers**).
2. Check if Cloudflare's **"Managed robots.txt"** or automated robots header injection is enabled.
3. If Cloudflare manages your `robots.txt`, it may overwrite the directives defined in your project repository (`dist/robots.txt`).
4. **Recommended Action:**
   - **Disable Cloudflare Managed robots.txt** so that Cloudflare serves the exact `robots.txt` generated by `scripts/build.mjs`.
   - Your static `robots.txt` contains explicit permissive directives for Googlebot, Mediapartners-Google, and AdsBot-Google.

---

## 3. Configure Bot Fight Mode & WAF Custom Rules
1. In Cloudflare Dashboard, navigate to **Security** → **Bots**.
2. If **Bot Fight Mode** (free plan) or **Super Bot Fight Mode** (pro plan) is enabled:
   - Bot Fight Mode issues JavaScript challenges or managed challenges to suspicious user agents.
   - Although Cloudflare attempts to whitelist verified search engines, network glitches or DNS reverse-lookup failures can trigger false positives on Googlebot or Mediapartners-Google.
3. **Recommended WAF Bypass Rule:**
   - Navigate to **Security** → **WAF** → **Custom Rules**.
   - Create a rule titled: `Allow Verified Search Bots and Google AdSense`.
   - Expression:
     ```
     (cf.client.bot) or (http.user_agent contains "Googlebot") or (http.user_agent contains "Mediapartners-Google") or (http.user_agent contains "AdsBot-Google")
     ```
   - Action: **Skip** → check **All remaining security features** (including WAF Managed Rules, Bot Fight Mode, Rate Limiting).
   - Place this rule at the highest priority (Position 1).

---

## 4. Verify Raw robots.txt and ads.txt Availability via CLI
Run the following curl commands in a terminal to verify that your live domain responds with `HTTP 200 OK` and delivers the expected content without a Cloudflare challenge page:

### A. Test robots.txt as Googlebot
```bash
curl -I -A "Mozilla/5.0 (compatible; Googlebot/2.1; +http://www.google.com/bot.html)" https://fingtaj.online/robots.txt
```
**Expected Result:**
- HTTP status: `HTTP/2 200`
- Content-Type: `text/plain`
- Response body must match `dist/robots.txt` exactly.
- Confirm there is no `cf-mitigated: challenge` header.

### B. Test ads.txt as Mediapartners-Google
```bash
curl -i -A "Mediapartners-Google" https://fingtaj.online/ads.txt
```
**Expected Result:**
- HTTP status: `HTTP/2 200`
- Response body must contain:
  ```
  google.com, pub-3594420471814241, DIRECT, f08c47fec0942fa0
  ```

### C. Test Sample Calculator and Guide Pages
```bash
curl -I -A "Mediapartners-Google" https://fingtaj.online/stamp-duty-calculator
curl -I -A "Mediapartners-Google" https://fingtaj.online/guides/stamp-duty-and-registration-explained
```
**Expected Result:**
- HTTP status: `HTTP/2 200` for both URLs.

---

## 5. Raw HTML Rendering Verification
AdSense crawlers evaluate static text in the initial HTTP payload. All content on Fingtaj is generated statically at build time into pure HTML files:
- Verify that guide text, headings (`<h1>`, `<h2>`), worked examples, and tables are fully visible in the raw source without requiring client-side JavaScript execution.
- You can test this by running:
  ```bash
  curl -s https://fingtaj.online/guides/land-measurement-units-in-india | grep -C 3 "Land Measurement Units in India"
  ```
  If the heading and paragraphs appear in the output, static rendering is verified.
